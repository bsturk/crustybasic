# crustyBASIC on Commodore 128

Use `@OPTION TARGET c128` for the default Commodore 128 profile. It
builds a BASIC-loaded `.prg` for native C128 mode.

Portable runtime calls are documented in [`../API.md`](../API.md).
This page covers C128 systems, modes, formats, and hardware notes. For
command-line target selection and dialects, see
[`../USAGE.md`](../USAGE.md).

## Systems

| System | Default output | Notes |
| --- | --- | --- |
| `c128.orig` | `.prg` | Default. C128 native mode with BASIC 7.0 and KERNAL ROMs. |

Loaded `.prg` builds use the resident BASIC 7.0 ROM for `REAL` by
default and when optimizing for size. Speed builds use crustyBASIC's
built-in `REAL` support, as do cartridge builds.

## Basics

| Item | Value |
| --- | --- |
| CPU | 8502, with Z80 select exposed through the MMU |
| Text | 40x25 VIC-IIe and 80x25 VDC |
| Code start | `$1C10` for `.prg`, `$8000` for cart |
| Program RAM top | `$8000`, or `$C000` with `NOBASIC` |
| Text screen | `$0400` |
| Color RAM | `$D800` |
| String encoding | PETSCII |
| Main chips | VIC-IIe, VDC, SID, MMU |
| Recursive PROCs | Yes |

The current target stays in native C128 mode. It does not use `GO64`.

## Program memory

Normal PRG and disk builds use `$1C10-$7FFF` for code and data.
Select `@OPTION NOBASIC TRUE` or `--set nobasic=true` to add the
16 KB at `$8000-$BFFF`. These builds use built-in math, retain KERNAL
I/O, and restore the original memory configuration when the program ends.
Screen, character, and bitmap memory used by the program is reserved
automatically.

## Scrolling

The portable scrolling API supports horizontal and vertical pixel scrolling
in 40 column cell mode (`DISPLAY CELL`). Both `VICII_BANK` settings work.
The backing buffer is 40x25 cells; enabling both axes gives a 38x24 view.
Scrolling uses one shared cell color and does not scroll individual cell colors.
VDC scrolling is not supported by this API.

With `VICII_BANK 1`, scrolling reserves `$4400-$47FF`, `$4C00-$4FFF`, and
`$7000-$77FF` for its two screens and font. Bank 2 uses `$8400-$87FF`,
`$8C00-$8FFF`, and `$B000-$B7FF`.

`SCROLL_BEGIN_REGION` scrolls a band of rows sideways while the rows above
and below it stay still, in VIC-IIe bank 1:

```basic
SCROLL_BEGIN_REGION 0, 2, 40, 20, 8, 0
```

The band always spans the full width and does not scroll vertically. It is
shown from two spare screen matrices at `$7800` and `$7C00` that a raster
interrupt switches in at the top of the band and out at its bottom, so the
fixed rows keep their cells, colors and the program's charset. The switch
happens in the last raster line of the row above the band and of the band's
last row; keep the cells at the right edge of those two rows blank to avoid
a flicker there. The band is copied a column sideways over the frames
between two cell crossings, half its rows per frame, so moves of up to 4
pixels a frame keep an even frame cost. Hardware sprites work over the band.
Their pointers are copied into the band matrices every frame, so write them
as usual and move sprites right after `SCROLL_PRESENT` returns.

`VICII_SCROLL_REGION_DISPLAY mode, charset` gives the band its own display
mode (`CELL`, `CELL_MULTICOLOR` or `VICII_TEXT_ECM`) and 2K aligned charset
inside the video bank, while the fixed rows keep the program's. KERNAL
keyboard input and the clock keep running while a band scrolls.
`SCROLL_BEGIN` or the end of the program ends the band.

A band can also scroll over a `DISPLAY_MIXED` screen. Call `DISPLAY_MIXED`
first and leave at least one bitmap row between the band and the text rows.
The band matrices share memory with the bitmap from row 19 on, so let the
text rows cover rows 19 to 24.

## BASIC 7.0 machine code calls

The `cbm_basic_v7_0` dialect accepts `SYS address[,A[,X[,Y[,S]]]]`.
Calls use the bank selected by `BANK`. Omitted registers keep the values
returned by the previous `SYS` call.
`SYS` reserves `$03E4-$03EF` for the call.

`RREG A,X,Y,S` reads the returned accumulator, X, Y, and status values.
Leave fields empty to skip registers, for example `RREG ,X,,S`.

## VIC-IIe Graphics

The `VIC` namespace exposes the VIC-IIe register set:

| Name | Purpose |
| --- | --- |
| `VIC.BORDER` | Border color. |
| `VIC.BACKGROUND` | Background color. |
| `VIC.SPRITE_ENABLE` | Enable sprite bits. |
| `VIC.SPRITE_X_MSB` | High X bits for all sprites. |
| `VIC.SPRITE0_X` through `VIC.SPRITE7_Y` | Sprite positions. |
| `VIC.SPRITE0_COLOR` through `VIC.SPRITE7_COLOR` | Sprite colors. |
| `VIC.SPEED` | 1 MHz / 2 MHz control. |

C128 graphics support VIC-IIe text/cell mode, VIC-IIe bitmap modes, and
VDC 80 column text and 640x200 monochrome bitmap modes. The default
graphics mode is `VICII_BITMAP_HIRES`.

| Mode | C128 mode | Size | Colors |
| --- | --- | --- | --- |
| `VICII_TEXT` | VIC-IIe 40 column text | 40x25 | text |
| `VICII_BITMAP_HIRES` | VIC-IIe hi-res bitmap | 320x200 | 2 |
| `VICII_BITMAP_HIRES_TEXT` | VIC-IIe hi-res bitmap with default text window | 320x160 | 2 |
| `VICII_BITMAP_MULTICOLOR` | VIC-IIe multicolor bitmap | 160x200 | 4 |
| `VICII_BITMAP_MULTICOLOR_TEXT` | VIC-IIe multicolor bitmap with default text window | 160x160 | 4 |
| `VDC_TEXT` | VDC 80 column text | 80x25 | text |
| `VDC_BITMAP_HIRES` | VDC monochrome bitmap | 640x200 | 2 |

The portable display mode constants are also accepted where they map
cleanly to C128 hardware:

| Mode | C128 mode | Size | Colors |
| --- | --- | --- | --- |
| `CELL` | VIC-IIe 40 column text | 40x25 | text |
| `BITMAP_HIRES` | VIC-IIe hi-res bitmap | 320x200 | 2 |
| `BITMAP_LORES` | not supported | | |
| `BITMAP_MULTICOLOR` | VIC-IIe multicolor bitmap | 160x200 | 4 |
| `CELL_MULTICOLOR` | not supported | | |
| `VICII_TEXT_ECM` | VIC-IIe extended background color text | 40x25 | 2 per cell |

`DISPLAY VICII_TEXT_ECM` selects extended background color text. Each cell
has one foreground color from the full palette and one of four shared
backgrounds set with `BACKGROUND_COLOR index, color`, using indices `0`
through `3`. `BACKGROUND_COLOR color` sets background `0`.
`CELL_PUTC` bits 0 through 5 select glyph 0 through 63 and bits 6 and 7
select the background.

The default target uses VIC-IIe bank 1 (`$4000-$7FFF`), with screen
attributes at `$5800` and bitmap data at `$6000`. Select `@OPTION
VICII_BANK 2` for bank 2 (`$8000-$BFFF`), with screen attributes at
`$8400` and bitmap data at `$A000`.

`VICII_BITMAP_HIRES_TEXT` and `VICII_BITMAP_MULTICOLOR_TEXT` are native
C128 modes with a five row text window at the bottom. The portable
`DISPLAY_MIXED` interface supports `BITMAP_HIRES`, `VICII_BITMAP_HIRES`,
`BITMAP_MULTICOLOR`, and `VICII_BITMAP_MULTICOLOR`. It places one full
width text region anywhere in the 40x25 text grid, and cell calls use
absolute row numbers. The BASIC 7.0 dialect keeps its native bottom window
behavior for `GRAPHIC 2` and `GRAPHIC 4`, including their split line
argument.

`DISPLAY_MIXED` installs and starts its raster program. `RASTER_STOP` leaves
the VIC-IIe in full bitmap mode while preserving that program.
`RASTER_START` resumes it, and `RASTER_UNINSTALL` removes it.

`GFX_PAGE_COUNT`, `GFX_PAGE_SELECT`, `GFX_PAGE_DRAW`, `GFX_PAGE_BASE`, and
`GFX_PAGE_ATTR_BASE` are available through the portable graphics API. On
C128 they return one VIC-IIe page in normal graphics modes. In 80 column
mode they expose two VDC text pages, including separate text and
attribute bases. In `VDC_BITMAP_HIRES` they expose one 16000 byte
bitmap page on 16K VDC systems and four monochrome bitmap pages on 64K
VDC systems. With VDC `EXTMEM`, two bitmap pages remain available.
`GFX_PAGE_SELECT` changes the visible page. `GFX_PAGE_DRAW` selects the
page used by drawing calls, or by text output in 80 column mode.

## Charset and Tiles

The C128 target supports 8 byte writable glyphs for VIC-IIe 40 column
text through the portable `CHARSET_*` API. `CHARSET_COPY_DEFAULT`
copies the glyphs from the ROM font into a writable charset and activates
it. `CHARSET_INSTALL src_addr` copies and activates a complete 2048 byte
charset. The target chooses a writable charset page and text screen in the
bank selected by `VICII_BANK`.

In cell mode, `TILE_DEFINE` writes each defined glyph to both the
VIC-IIe RAM charset and the VDC character pattern table, so the same
tile definitions work on the 40 and 80 column text paths. Passing a base
to `TILE_BEGIN span_w, span_h, base` selects another 2K-aligned VIC-IIe
charset page; VDC tile glyphs use `VDC.CHARSET_DEFAULT_BASE`.

`TEXT_SELECT_80()` selects the 80 column editor,
`TEXT_SELECT_40()` selects the 40 column editor, and
`TEXT_IS_80()` reports the current editor screen. `GRAPHIC 5` in
the `cbm_basic_v7_0` dialect maps to 80 column text.

The two built in VDC pages use `$0000/$0800` and `$1000/$1800` inside
VDC RAM for text and attributes.

`VDC.BURST_*` skips per byte VDC ready polling after setup. Use it only
from a known safe VDC retrace window, usually after `VDC.WAIT_VBLANK()`,
and keep counts small enough.

`DISPLAY(VDC_BITMAP_HIRES)` configures a 640x200 two color bitmap
where `GFX_ROW_BYTES()` returns `80`. `CLS`, `COLOR`, `PLOT`, `UNPLOT`,
`POINT`, `HLINE`, `UNHLINE`, and the higher level line, box, and circle
helpers use VDC VRAM through the graphics API. `GFX_PAGE_BASE(0)` and
`GFX_PAGE_BASE(page)` return VDC RAM offsets, not CPU addresses.

## Extended Memory

The C128 exposes these EXTMEM handles:

| Handle | Memory |
| --- | --- |
| `EXTMEM_DEFAULT` | The target default selected for calls without a handle. |
| `EXTMEM_MMU` | Internal C128 RAM bank 1. |
| `EXTMEM_REU` | REU memory using physical REU bank numbers. |
| `EXTMEM_VDC` | The reserved upper 32K of 64K VDC RAM, available with `@OPTION EXTMEM VDC`. |

Without `@OPTION EXTMEM`, calls without a handle keep the normal C128
mapping. EXTMEM bank 0 uses internal RAM bank 1. Banks 1 and up use REU
physical banks 0 and up. When a mapper owns internal RAM bank 1, the
default mapping starts with REU physical bank 0 instead.

Explicit handles do not use that combined numbering. `EXTMEM_MMU` has one
62K bank covering internal RAM bank 1 `$0400-$FEFF`, so valid offsets are
`$0000-$FAFF`. `EXTMEM_REU` bank `N` is physical REU bank `N`.

Select VDC RAM as the default provider with:

```basic
@OPTION EXTMEM VDC
```

This reserves VDC `$8000-$FFFF`. `EXTMEM_VDC` has one 32K bank, so valid
addresses use bank 0 and offsets `$0000-$7FFF`. It is available only when
`VDC.HAS_64K()` succeeds. `COUNT = 0` requests 65536 bytes and is therefore
too large for this provider.

The reservation leaves VDC bitmap pages 0 and 1 available. Pages 2 and 3
are unavailable because they overlap the reserved range. Raw `VDC.POKE`,
`VDC.PEEK`, and `VDC.FILL` calls remain absolute and can overwrite the
reservation.

An REU can be used at the same time by passing its handle:

```basic
@OPTION EXTMEM VDC

EXTMEM_STASH 256, ADDR BUFFER, 0, 0
EXTMEM_STASH EXTMEM_REU, 256, ADDR BUFFER, 0, 1
```

`EXTMEM_AVAILABLE(EXTMEM_MMU)` returns `0` when the active mapper owns
internal RAM bank 1. Transfer calls do not add range or ownership checks.

### REU image

`EXTMEM_IMAGE_SUPPORTED` is `TRUE`. Assets included with `EXTMEM` go into an
REU image written beside the program with a `.reu` extension. Fetch them with
the `EXTMEM_REU` handle:

```basic
@INCLUDE_FILE LEVELS "levels.bin" EXTMEM

EXTMEM_FETCH EXTMEM_REU, LEVELS_LEN, ADDR LEVELS, LEVELS_XADDR, LEVELS_BANK
```

The image is 512 KB unless `@OPTION EXTMEM_IMAGE_KB` picks 128, 256, 1024,
2048, 4096, 8192, or 16384. VICE only loads an image that matches its REU
size:

```
x128 -reu -reuimage hello.reu hello.d81
```

Add `-reusize n` when `EXTMEM_IMAGE_KB` is not 512. On an Ultimate, load the
`.reu` file into the REU before starting the program. When
`@OPTION MAPPER overlay(REU, n)` keeps overlays in the REU, the assets skip
bank `n`.

## Images

Native image display supports C64 compatible VIC-IIe bitmap descriptors:

| Format | Description |
| --- | --- |
| `IMAGE_FMT_C64_MULTI` | Koala Painter, 10003 bytes, load address `$6000`, including `$FE` RLE variants |
| `IMAGE_FMT_C64_HIRES` | Art Studio, 9002-9009 bytes, load address `$2000` |

At build time, `cb-image` and `@INCLUDE_IMAGE` also accept untiled 40x25
CharPad CTM9 bitmap projects in hires and multicolor modes.

Prepared Koala and Art Studio images use the same RLE format as the C64
when it makes the stored image smaller.

Image wipes, slides, fades, and dissolves support both formats on the 40 column
VIC-IIe display. Wipes and slides work in all four directions. Fades use four
brightness steps. Dissolves support 1, 2, 4, or 8 pixel square blocks.
Effects that reveal an image need unpacked image data in memory; use
`UNPACKED` with `@INCLUDE_IMAGE`. Fade out and dissolve out use the current
bitmap. VDC image effects are not supported.

Runtime image file loading is not available.

## MMU and CPU

The `MMU` namespace exposes the C128 MMU registers at `$D500` through
`$D50B`, including `MMU.CONFIG`, `MMU.MODE_CONFIG`, `MMU.RAM_CONFIG`,
`MMU.PAGE0_LO`, `MMU.PAGE0_HI`, `MMU.PAGE1_LO`, `MMU.PAGE1_HI`, and
read only `MMU.VERSION`.

Low level helpers are available. MMU page arguments are 256 byte page
selectors, not byte addresses. Page `$20` maps address `$2000`; page
`$100` maps banked address `$10000` on hardware that exposes that MMU
address bit.

| Call | Purpose |
| --- | --- |
| `MMU.CONFIG_SET VALUE` | Set the current memory configuration through `$FF00`. |
| `MMU.CONFIG_CURRENT()` | Read the current memory configuration through `$FF00`. |
| `MMU.CPU_SELECT CPU_8502` | Select the 8502 side of the MMU CPU bit. |
| `MMU.CPU_SELECT CPU_Z80` | Select the Z80 side of the MMU CPU bit. |
| `MMU.CPU_CURRENT()` | Read the current MMU CPU bit. |
| `MMU.CPU_IS_8502()` | Report whether the MMU CPU bit selects 8502. |
| `MMU.CPU_IS_Z80()` | Report whether the MMU CPU bit selects Z80. |
| `MMU.CHAR_ROM_MAP` | Map character ROM at `$D000` and switch out I/O. |
| `MMU.CHAR_ROM_UNMAP` | Restore I/O at `$D000`. |
| `MMU.CHAR_ROM_PEEK(OFFSET)` | Temporarily map character ROM, read one byte, then restore the previous config. |
| `MMU.CHAR_ROM_COPY OFFSET, DST, COUNT` | Temporarily map character ROM, copy bytes to RAM, then restore the previous config. |
| `MMU.PAGE0_MAP PAGE`, `MMU.PAGE1_MAP PAGE` | Raw zero page and stack page remap. |
| `MMU.PAGE0_CURRENT()`, `MMU.PAGE1_CURRENT()` | Read the current zero page or stack page selector. |
| `MMU.PAGE0_DEFAULT`, `MMU.PAGE1_DEFAULT` | Restore the zero page or stack page window to page `$00` or `$01`. |
| `MMU.PAGE0_PEEK`, `MMU.PAGE0_POKE`, `MMU.PAGE0_FILL` | Temporary zero page window operations. |
| `MMU.PAGE1_PEEK`, `MMU.PAGE1_POKE`, `MMU.PAGE1_FILL` | Temporary stack page window operations. |
| `MMU.PAGE0_COPY_FROM PAGE, SRC`, `MMU.PAGE1_COPY_FROM PAGE, SRC` | Copy 256 bytes from RAM into the remapped page. |
| `MMU.PAGE0_COPY_TO PAGE, DST`, `MMU.PAGE1_COPY_TO PAGE, DST` | Copy 256 bytes from the remapped page into RAM. |

CrustyBasic emits 8502 code for C128. The Z80 select constant
and helper are low level hardware controls, not Z80 code generation or a
CP/M runtime.

## Sprites

The C128 target uses eight VIC-IIe hardware sprites.

| `SPRITE_DEFAULT_MODE` | `SPRITE_WIDTH` x `SPRITE_HEIGHT` | Artwork row | Visible colors | Data |
| --- | --- | --- | --- | --- |
| `SPRITE_MODE_HIRES` (default) | 24x21 footprint | 24 one bit cells | 1 | 63 bytes |
| `SPRITE_MODE_MULTICOLOR` | 24x21 footprint | 12 two bit cells displayed double wide | 3 | 63 bytes |

`SPRITE_WIDTH` remains 24 because sprite coordinates and bounds use the
displayed footprint.

`SPRITE_DATA_8X8` expands an eight byte shape into a centered 24x21
hardware sprite. `SPRITE_EXPAND` can display a sprite at 48x42. Both
modes keep per sprite X and Y expansion, priority, and collision latches.

`SPRITE_DATA` copies the same 63 target native bytes in either mode. In
multicolor data, `00` is transparent, `01` is shared `SPRITE_COLOR2` at
`$D025`, `10` is per sprite `SPRITE_COLOR` at `$D027+id`, and `11` is
shared `SPRITE_COLOR3` at `$D026`.

`SPRITE_DEFAULT_MODE` selects the reset mode. `SPRITE_MODE id, mode` changes
one sprite without changing the others. Direct `VIC.SPRITE_MULTICOLOR` bits
remain available.

`SPRITE_SHAPE_SLOTS` is 32. `SPRITE_SHAPE_INSTALL slot, addr` copies a 63 byte
shape to `VICII_SPRITE_SHAPE_BASE + slot * 64`, the first 2K of the bank's
bitmap area (`$6000` in bank 1, `$A000` in bank 2), and `SPRITE_SHAPE_SELECT
id, slot` points a sprite at it through the screen the KERNAL shows. The
slots share memory with the hires bitmap, so use them with text displays.

## SID Sound

The shared SID calls and constants are documented under
[C64 SID Sound](C64.md#sid-sound). The C128 target supports one SID at
`$D400` and does not use `SID_CHIPS`.

Timed sound scheduling is available through the portable
`SOUND_TIMED_*` API. The C128 provider uses the shared chained IRQ
dispatcher, uses 60 Hz `TICKS` units, and returns from timed note calls
immediately.

The portable `EVENT_*` API maps `EVENT_SPRITE_SPRITE`,
`EVENT_SPRITE_BG`, and `EVENT_LIGHTPEN` to VIC-IIe IRQ sources.
Subscribed handlers must be no argument PROCs and run from the same
shared IRQ dispatcher as timed sound.

The `cbm_basic_v7_0` dialect includes a synchronous compiled `PLAY`
path for note letters, rests, note lengths, dotted notes, sharps/flats,
`V/O/T/X/U/M` music string commands, `TEMPO`, and shared
envelope/filter state. Notes and rests are scheduled through the C128
timed sound provider, so different SID voices can overlap. `PLAY` still
parses the music string in the foreground and waits when reusing an
active voice or processing `M`.

## Input

| Capability | Value |
| --- | --- |
| Keyboard | Yes |
| Individual held keys | Yes |
| Joystick ports | 2 |
| Buttons | 1 per port |
| Stick type | Digital |
| Paddle axes | 4 |
| Keypad ports | 0 |
| Keypad `INPUT` | No |
| Mouse buttons | 0 |

Paddle reads use SID `POTX`/`POTY`. Trigger reads follow the native
active-low convention: `0` means pressed, `1` means released.

`KEY_HELD(code)` scans the C128 keyboard matrix without consuming typed
input. It supports `KEY_SPACE`, `KEY_0` through `KEY_9`, and `KEY_A`
through `KEY_Z`.

In the `cbm_basic_v7_0` dialect, `JOY(1)` and `JOY(2)` use BASIC 7's
one based joystick numbering and return compass direction values with
128 added when fire is pressed. `POT(1)` through `POT(4)` return raw
paddle values with 256 added when the matching trigger is pressed.
`PEN(0)` and `PEN(1)` read the VIC-IIe light pen position; `PEN(2)`,
`PEN(3)`, and `PEN(4)` read the VDC light pen horizontal position,
vertical position, and trigger state.

## Timing

Delay is available through the runtime throttle. `TICKS` reads the
60 Hz KERNAL jiffy clock and advances without `FRAME_WAIT`. The 24 hour
wrap is compensated for one crossing. `TIMER_SUPPORTED` is false, so the
elapsed timer API is not available.

The CBM clock calls are specific to this target family:

| Call | Purpose |
| --- | --- |
| `TI` | Read the 24 bit KERNAL jiffy clock as `U32`. |
| `TI_SET jiffies` | Set the KERNAL jiffy clock from the low 24 bits. |
| `TI$` | Return the clock as a six character `HHMMSS` string. |

`TICKS` uses `TI` as its source. `TICKS_RESET` records a new starting
value without changing the KERNAL clock.

`FRAME_WAIT`, `FRAME_INSTALL`, and `FRAME_UNINSTALL` are available
through a synthesized raster wait hook.

`@PERIODIC IRQ` runs from the system interrupt alongside timed sound and
events. Music and sprite updates can continue during `FILE_LOAD`.
Loads with this service active keep sprites visible and use 1 MHz,
then restore the previous speed and sprite ownership setting.

## Text

`TEXT_ENCODING` defaults to `UPPER_CASE`: `A-Z` maps to `$41-$5A`,
`a-z` maps to `$61-$7A`, and a newline maps to `$0D`.

For both letter cases, use `@OPTION TEXT_ENCODING MIXED_CASE` and
`PRINT "{LOWER}";`. This encoding maps `A-Z` to `$C1-$DA` and `a-z`
to `$41-$5A`. `UPPER` and `LOWER` string functions follow the encoding.

Startup preserves the selected letter case. Printing `{LOWER}` selects
mixed case; `{UPPER}` selects uppercase and graphics. These controls
affect the whole screen. Returning to BASIC keeps that selection.

Use `{$NN}` for an exact PETSCII byte. The CBM BASIC dialect also maps
`~` to `$FF` for VICE petcat listings. Common escapes:

| Escape | Byte |
| --- | --- |
| `{RETURN}`, `{ENTER}` | `$0D` |
| `{TAB}` | Four spaces |
| `{CLEAR}`, `{CLR}` | `$93` |
| `{HOME}` | `$13` |
| `{LOWER}`, `{TEXT_LOWER}` | `$0E` |
| `{UPPER}`, `{TEXT_UPPER}`, `{GRAPHICS}` | `$8E` |
| `{LEFT}`, `{RIGHT}`, `{UP}`, `{DOWN}` | Cursor controls |
| `{RVS_ON}`, `{RVS_OFF}` | Reverse video controls |

The cell API writes directly to the 40x25 screen at `$0400` and color
RAM at `$D800`. `CELL_CODE` converts ASCII-style characters to screen
codes.

## Files

`FILE_LOAD_PROGRAM(path$)` loads a PRG from disk device 8 using its
stored address. `FILE_LOAD_PROGRAM(path$, dst)` uses `dst` instead.
Both skip the two address bytes and load the remaining file through
KERNAL LOAD. They return zero on success or the KERNAL error code,
without running the loaded code.
Loading uses RAM bank 0.

File channels run from 1 to 15. `FILE_OPEN` uses disk device 8, and the
KERNAL allows up to 10 files open at once. C128 specific opens can choose
another device or secondary address.

The lower KERNAL channel helpers are also callable by target-specific
programs: `OPEN_CH`, `CLOSE_CH`, `GET_CH`, `PUT_CH`, `PRINT_CH_STR`,
`ST`, and `CMD_CH`.

Select disk output with `@OPTION OUTPUT_TYPE disk` or
`--set output-type=disk`. The result is a `.d81` image containing the
program and files staged by two-path `@INCLUDE_*` forms. Programs built for
several targets can use `disk-image = true` to add the image where the
target supports one.

## Banked memory

Select an overlay mapper and normal disk output with:

```basic
@OPTION TARGET c128
@OPTION OUTPUT_TYPE disk
@OPTION MAPPER overlay
```

This uses internal C128 RAM by default. `overlay8` selects the larger 8K
window.

Use an REU and choose its physical 64K bank explicitly with:

```basic
@OPTION MAPPER overlay(REU, 0)
```

The program then requires an REU. Startup stores each overlay bank there
with DMA, and bank switches fetch it back into the overlay window. The REU
bank number is not a default `EXTMEM` number. The `EXTMEM_REU` handle uses
physical REU bank numbers, so do not use the mapper's selected physical
bank through that handle.

When the output file is named with a `.d81` extension, disk output is
selected automatically.

## Cartridges

Select cartridge output at build time with `--set output-type=cart`:

```text
crustybasic build <input.cbs> --set output-type=cart -o program.bin
```

Use source-level `OUTPUT_TYPE` only when the program should always build
as a cart:

```basic
@OPTION TARGET c128
@OPTION OUTPUT_TYPE cart
```

Default carts use native 16K raw `.bin` external function ROM output at
`$8000`. The startup stays in C128 mode and runs through the C128
function ROM path. C64 style cartridges are a separate format and
normally switch the machine into C64 mode.

## Dialects

`cbm_basic_v7_0` targets `c128` by default. It supports Commodore
suffix rules and rewrites the C128 BASIC 7.0 graphics commands
`GRAPHIC`, `SCNCLR`, `COLOR`, `CHAR`, `LOCATE`, `DRAW`, `BOX`,
`CIRCLE`, `PAINT`, `WIDTH`, and `SCALE`; sound commands `VOL`, `SOUND`,
`ENVELOPE`, and `FILTER`; a synchronous compiled `PLAY` subset for
note letters, rests, and note lengths plus `TEMPO`; a compiled
`COLLISION` subset for
enabling or disabling VIC collision and lightpen event sources; sprite
commands `SPRITE`, `MOVSPR`, `SPRCOLOR`, and `SPRSAV`; `BANK` for
`PEEK` and `POKE`; graphics readback functions `RCLR`, `RDOT`, and
`RGR`; input readback functions `JOY`, `POT`, and `PEN`; sprite
readback functions `RSPCOLOR`, `RSPPOS`, `RSPRITE`, and `BUMP`; text
window commands `WINDOW` and `RWINDOW`; and speed
commands `FAST` and `SLOW` to native C128 runtime helpers.

`GRAPHIC 5` switches to 80 column text. `GRAPHIC 2` and `GRAPHIC 4`
use the native VIC-IIe bottom text window and accept the `s` split line
argument.

`WIDTH 1` selects single width graphics drawing. `WIDTH 2` selects a
compiled double width path for `DRAW`, `BOX`, and line segments emitted
by advanced circle and arc forms.

`SCALE 1` selects BASIC 7.0 scaled graphics coordinates using 1023 by
1023 in standard bitmap modes and 511 by 511 in multicolor bitmap
modes. `SCALE 1, XMAX, YMAX` selects explicit coordinate ranges. Bare
`SCALE` disables scaling. Scaling affects compiled graphics coordinates
and `MOVSPR`; `RDOT` and `RSPPOS` report the scaled state.

In Commodore BASIC dialects, `RND(X)` returns a `REAL` fraction from
`0` up to, but not including, `1`. Use `RAND(N)` for portable bounded
integers.
